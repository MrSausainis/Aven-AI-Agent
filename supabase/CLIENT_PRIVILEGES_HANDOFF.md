# Client privileges (W27)

Applied to Supabase project upiadmvxzphegivqszvp as migration 20260930163925_client_column_privileges on 2026-09-30. Baseline reproduction with a synthetic signup confirmed that authenticated users could change profiles.created_at. Original four public application tables granted both client roles SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER; RLS protected many row operations but did not restrict profile columns. No real account data was changed during reproduction.

The migration revokes client/PUBLIC grants on profiles, entitlements, tiers and reviews, then explicitly grants the required operations. Anonymous clients may SELECT public tiers/reviews. Authenticated clients may SELECT their own profiles/entitlements through RLS and update only profiles.account_name/preferred_theme. Neither profile id/created_at nor billing/catalog fields can be written directly. Authenticated review INSERT/UPDATE/DELETE remains compatible with the existing browser UPSERT and the W07 owner/name/server-time trigger. Administrative TRUNCATE/TRIGGER/REFERENCES privileges are removed from both client roles on all four tables. Existing service_role, admin view, server triggers and internal billing-table permissions remain unchanged.

Policies explicitly target the intended client roles. Profile/review UPDATE policies now have explicit matching ownership USING/WITH CHECK expressions. SELECT ownership and public catalog/review access remain as before. No new functions, privileged execution boundaries or user_metadata authorization were added. This migration targets these existing tables, not project-wide default privileges for every future table.

Verification: supabase/tests/client-column-privileges.sql passed real authenticated/anonymous/service_role operations using synthetic auth signup rows and ROLLBACK. It verifies private row visibility, foreign-row update denial, server-only columns, canonical name/theme entitlement sync, browser-style review UPSERT/delete, anonymous public reads, denied anonymous writes/private reads, retained server entitlement writes and absence of administrative/client access to internal tables/admin view. Existing review-integrity.sql and account-name-policy.sql passed as regressions. Three original users/profiles remained; profiles and reviews fingerprints matched baseline. Security advisors added no warnings; existing W08 leaked-password protection warning and three intentional internal-table RLS/no-client-policy information notices remain.

Rollback: supabase/rollback/client-column-privileges.sql restores the exact captured pre-W27 client grants and policy expressions, reopening the original issue. No data rollback is needed. Static publishing continues to exclude migrations, SQL tests and handoffs. Real browser signup, account settings, review operations and desktop account access remain part of the agreed final live pass.

Primary references: https://supabase.com/docs/guides/database/postgres/column-level-security and https://www.postgresql.org/docs/17/sql-grant.html. Table UPDATE grants override column restrictions, so the table grant was removed before adding the two allowed column grants.
